# Plano de Refatoração: AdminDashboard

## Análise do Estado Atual

O `AdminDashboard` atual é um componente monolítico com ~1200 linhas que:
- Mistura lógica de fetch, filtros, handlers e renderização
- Não usa `useCallback` nos handlers (causa re-renders desnecessários)
- Carrega todos os dados de uma vez (sem separação essencial/secundário)
- Usa `cache: 'no-store'` em vez de `revalidate` apropriado
- Tabs estão embutidas (dificulta lazy loading futuro)

## Objetivos da Refatoração

1. **Performance**: Reduzir re-renders com `useCallback` e `useMemo`
2. **Organização**: Separar concerns em componentes menores
3. **Cache inteligente**: Dados essenciais (stats, eventos, jogos) com revalidate curto (20-30s); dados secundários com revalidate longo (60s+)
4. **Manutenibilidade**: Código limpo, tipado e testável
5. **Escalabilidade**: Preparado para lazy loading das tabs pesadas

## Mudanças Técnicas

### 1. AdminDashboard.tsx (principal)
- Reduzido para ~300-400 linhas
- Apenas estado global + fetchData otimizado
- Handlers com `useCallback`
- Renderização das tabs delegada a componentes filhos
- Modals mantidos no topo (controlados pelo estado principal)

### 2. fetchData refatorado
```typescript
const fetchData = useCallback(async () => {
  // Dados ESSENCIAIS (sempre carregados)
  const [stats, eventos, jogos, users, vencedores] = await Promise.all([
    getApi('/api/dashboard/stats', 20),
    getApi('/api/eventos', 30),
    getApi('/api/jogos', 30),
    getApi('/api/users', 40),
    getApi('/api/participacoes?ganhador=true', 30),
  ]);

  // Dados SECUNDÁRIOS (condicionais por role)
  if (userRole === 'super_admin') {
    const [aldeias, transacoes, logs] = await Promise.all([
      getApi('/api/aldeias', 60),
      getApi('/api/admin/transacoes', 40),
      getApi('/api/admin/logs', 60),
    ]);
  }

  // Contadores pendentes (sempre necessários)
  const [pedidos, entregas] = await Promise.all([
    fetchPedidosPendentes(),
    fetchEntregasPendentes(),
  ]);
}, [token, aldeiaId, userRole]);
```

### 3. Handlers com useCallback
- `handleSaveEvento`
- `handleSaveJogo`
- `handleToggleJogoEstado`
- `handleSaveAldeia`
- `handleSaveUser`
- `handleConvertPremio`
- `handleDelete`
- `handleTestarJogo`

Cada handler recebe dados e callbacks necessários via props das tabs individuais.

### 4. Componentes de Tab individuais
Cada tab:
- Recebe apenas os dados que precisa como props
- Recebe handlers necessários como props
- Contém sua própria lógica de filtro/paginação (com `useMemo`)
- Mantém estado local (search, page)
- Exemplo: `EventosTab.tsx` recebe `eventos`, `onSave`, `onDelete`, `onEdit`

### 5. Filtros e paginação
Cada tab terá seus próprios estados de filter/page (não mais no estado global). Isto reduz re-renders desnecessários.

### 6. Tipagem
- Tipos explícitos para todas as entidades (Evento, Jogo, User, etc.)
- Interfaces para props de cada componente

| Risco | Mitigação |
|-------|-----------|

| Tipagem incompleta | Adicionar tipos gradualmente |

### Erro 4: Tipos incompatíveis nos `initialData` dos modais (linhas 821, 832, 839)
**Status:** ⚠️ **PENDENTE — Opção B selecionada**
Os modais usam tipos `JogoData`, `AldeiaData`, `UserData`. O AdminDashboard usa tipos próprios (`Jogo`, `Aldeia`, `User`) e passa `null`, causando incompatibilidade.

**Solução (Opção B — tipagem correta):**

**Passo 1:** Importar os tipos dos modais no AdminDashboard.tsx:
```typescript
import type { JogoData } from "@/components/modals/create-jogo-modal";
import type { AldeiaData } from "@/components/modals/aldeia-modal";
import type { UserData } from "@/components/modals/user-modal";
```

**Passo 2:** Alterar os tipos dos estados:
```typescript
// Antes:
const [selectedJogo, setSelectedJogo] = useState<Jogo | null>(null);
const [selectedAldeia, setSelectedAldeia] = useState<Aldeia | null>(null);
const [selectedUser, setSelectedUser] = useState<User | null>(null);

// Depois:
const [selectedJogo, setSelectedJogo] = useState<JogoData | null>(null);
const [selectedAldeia, setSelectedAldeia] = useState<AldeiaData | null>(null);
const [selectedUser, setSelectedUser] = useState<UserData | null>(null);
```

**Passo 3:** Atualizar a passagem de `initialData` nos modais:
```tsx
<CreateJogoModal
  ...
  initialData={selectedJogo ?? undefined}
/>
<AldeiaModal
  ...
  initialData={selectedAldeia ?? undefined}
/>
<UserModal
  ...
  initialData={selectedUser ?? undefined}
/>
```

**Nota:** Se houver conflito entre `JogoData` e o tipo `Jogo` interno (campos como `limitePorUsuario`, `modoSorteio`, etc.), a API deve retornar esses campos. Caso contrário, pode ser necessário adaptar os tipos ou usar `as any` temporariamente (Opção A). Mas a Opção B é a abordagem correta a longo prazo.
